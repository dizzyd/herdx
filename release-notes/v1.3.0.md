## A Mac's menu bar

HerdX had two menus and a handful of items in them. It now has the seven a Mac
app is expected to have, with each item where somebody would look for it: tabs
and panes are made in **Shell**, moved between in **Window** beside Minimize,
shown and hidden in **View** alongside the themes, and **Help** lists every
shortcut next to your own prefix bindings.

Which means the things that were simply absent are there — About, Services,
**Hide HerdX** (⌘H), Hide Others, Show All, Minimize, Zoom, **Enter Full Screen**
(⌃⌘F), Bring All to Front, and the list of open windows, which is the only way
back to a Settings window that has gone behind the terminal.

Undo, Redo, Cut, Copy, Paste and Select All sit in **Edit** and are aimed at
whatever holds the keyboard. The Settings and Machines windows are full of text
fields that have always had undo and never had a menu item to reach it by.

**⌘W closes what is in front of you.** With Settings or Machines up it closes
that window, and says so; over the terminal it is still Close Tab. Reaching for
the shortcut that closes a window no longer closes a herdr tab behind it.

Two new keystrokes: **⌃⌘S** shows and hides the sidebar, **⌃⌘F** goes full
screen. Menu items grey out when they cannot work rather than clicking and doing
nothing.

## Starting from nothing

A first run on a Mac without herdr used to be an empty window and a subtitle
reading `waiting for herdr… (no server)`. The install command was drawn into the
terminal as text nothing could select, and on the machines that most needed it —
the ones with no herdr at all — it never appeared, because it hung off a code
path that state could not reach.

Now the app says what is wrong, in a dialog with the command in a field you can
select and a button that copies it. **Help ▸ Install herdr…** is the way back to
it.

**And once herdr is installed, HerdX starts a session itself.** No trip to a
terminal to run `herdr` first; not even a relaunch, since the window notices
herdr arrive and starts a session on the spot. It starts one when there is none
to attach to — and leaves a session you stopped on purpose stopped.

The sidebar no longer greets a new user with `No such file or directory`.

## Knowing when there is a new HerdX

At startup, once a day at most, HerdX asks whether a newer version has been
released and says so if there is one. Never while you are working, and never
twice in a day however many times you restart it.

## Fixes

- **Removing a machine could cost you every machine.** herdr refuses a catalog
  whose selected machine is missing or disabled, and HerdX left the selection
  naming the one that had just gone — so the whole catalog stopped loading until
  the file was edited by hand.
- **A selection could crash the app.** Select near the right edge of a pane and
  then narrow it, and the range was built backwards.
- **A large image dropped the connection.** Frames carrying graphics were
  measured against the ordinary 2 MB limit rather than the graphics one, so a
  1024×1024 image disconnected the client — which then met the same image again
  as soon as it reconnected.
- **After reconnecting, the previous machine's output stayed on screen** until
  something new happened to arrive.
- **A window resized while connecting kept rendering at the old size**, and the
  focus that was never sent left this client unpromoted — which is how a host
  theme goes missing.
- **Hibernation is more careful.** A workspace holding a pane that was never
  examined is left alone, and the record survives a close whose reply was lost:
  that record is the only thing that still knows the session ids.
- **Copy-mode search goes to the match it chose** rather than sitting on the
  first hit with `n` doing nothing, and motions are asked one at a time, so
  pressing `w` twice quickly no longer spends the second keystroke.
- **The sidebar scrolls.** Past the bottom of the window the rows were laid out
  where nothing could reach them.
- **A click into a program using mouse reporting** no longer leaves it holding a
  press that never ends, and a drag that wanders out of the pane it started in
  is still measured against that pane.
- **A pane that stops having a cursor stops drawing one.**
- **A rejected command says what herdr actually said.** The reply is decoded
  rather than searched for the word "error", so a workspace you named `error` no
  longer reports a failure that never happened.

## Worth knowing

- **⇧⌘/ now opens the Help menu** rather than the shortcuts sheet directly. That
  keystroke belongs to macOS once an app has a Help menu, and Keyboard Shortcuts
  is the first item in it.
- **Themes and Machines moved.** Themes is in **View**, Machines is in the
  **HerdX** menu beside Settings. Their shortcuts are unchanged.
- Tab and pane navigation moved from Shell to **Window**, which is where the
  rest of the Mac keeps them. Those shortcuts are unchanged too.
