## Keeping the display awake

**Settings ▸ Keep awake** stops the display going dark while you are waiting on
something, which is what `caffeinate -d` in a spare terminal is usually for.

Set to *While an agent is working* it holds the display on only while some
agent is working or waiting on you, on any machine, and lets it sleep once they
are all done — so there is nothing to remember to turn off. *Always* is the
unconditional version. Either way it only prevents the display sleeping on its
own: closing the lid still sleeps.

An agent waiting on you counts, deliberately. A dark screen locks, and a locked
screen is also what silences the agent sounds — so sleeping through a question
is how you come back an hour later to an agent that asked one immediately.

## Hibernation is harder to surprise

Three ways a hibernating workspace could take work with it, all of them
hibernation trusting a reading that did not say what it was taken to say.

- **A background job behind an idle prompt was invisible.** herdr reports the
  pane's *foreground* job, so a shell with `npm run dev &` behind it looked
  idle — and closing the workspace ended the dev server, with nothing in the
  record that could bring it back. HerdX now checks what is actually running
  under each pane before it closes anything.
- **A pane that changed conversation mid-flight was closed anyway.** The
  checks ran before the close and compared pane ids; a pane that swapped one
  conversation for another passed both. The record then named the one that had
  gone, so closing ended the one that was there.
- **A workspace could be saved that can never come back.** Some agent session
  references cannot be resumed, and that was only discovered on the way back —
  by which point the workspace was gone and every attempt rolled back. Checked
  before anything closes now.

## Fixes

- **A stale `SSH_AUTH_SOCK` stopped every remote connecting.** If a shell
  profile named an agent socket that no longer exists, HerdX asked for it
  again, and again, without ever reaching `ssh` — so a machine whose key needs
  no agent at all sat on "connecting" forever.
- **Copy-mode search results off screen were thrown away.** A match above the
  visible rows moved the cursor without scrolling to it, and the next keypress
  put the cursor back. The pane now scrolls to the result.
- **`n` and `N` ignored which way you searched.** After a backward search `n`
  went forwards and `N` went backwards — both the wrong way round.
- **Select All then copy copied the wrong thing** when copy mode was open: the
  whole pane highlighted, two cells copied.
- **Mouse clicks in a pane reported the wrong column**, and right- and
  middle-button drags were not reported at all, so anything reading the mouse
  saw a click where there had been a drag.
- **The sidebar did not notice focus moving between two working agents** in the
  same tab, leaving the highlight — and keyboard navigation — on the old pane.
- **Switching machines did not tell the new one the window has focus**, so
  programs that react to focus stayed unfocused until you clicked away and
  back. The same was true after a reconnect, along with the terminal's colours.
- **Underlines and strikethroughs covered the wrong cells.** An underlined
  space drew nothing, and a plain gap between two underlined words was
  underlined along with them.
- **Setting up a new machine could type the installer into the wrong pane** if
  you clicked elsewhere while it was starting.
- **⌃b typed into a text field could close a pane.** Settings, the Machines
  sheet and every rename prompt now keep their own keystrokes, as does an input
  method mid-composition.
- **HerdX could quit outright** if the herdr server went away at the wrong
  moment during a hibernate or revive.
- **A machine that failed to connect sometimes explained itself with nothing at
  all**, and connections could accumulate invisibly when a reply never arrived.
