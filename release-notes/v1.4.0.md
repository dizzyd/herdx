## Worktrees

A worktree is a second checkout of a repo on another branch, and herdr treats
one as a workspace of its own. HerdX can now make them.

**New Worktree…** asks for a branch, suggesting a name so the common case is
one keystroke, and shows the directory it is about to land in as you type —
the one thing about a new worktree that is not obvious from its name and
cannot be found out afterwards without going to look. The branch is cut from
HEAD, and you end up in it.

**Open Worktree…** lists the repo's existing checkouts, saying which are
already open. **Remove Worktree…** deletes the checkout you are in — not its
branch, and not without asking. A checkout with uncommitted work in it is
refused rather than quietly discarded, and forcing it is a second, separate
question.

All three work on the repo the focused workspace belongs to, so new and open
start from the repo itself rather than from inside one of its worktrees, and
remove only applies inside one. herdr binds the first to a prefix chord
(⌃b ⇧G by default) and leaves the other two for you to bind; all three are in
the **Shell** menu either way.

## Two agents in one repo, side by side

Running a coder and a reviewer in the same repo, the Agents list put them
nowhere near each other: rows were titled by agent, so one kind per repo gave
a column of rows all called "claude", and because the list is banded by how
recently each agent did anything, a pair split the moment one of them went
quiet.

Agents sharing a repo are now drawn together, under whichever of them the
ordering put first. **Nothing moved** — a group sits exactly where its most
urgent member sat, so what just finished is still at the top where you look
for it. The repo is the row's name now, which also means it never truncates;
the machine is named only when more than one is attached.

## Waking from sleep

Close the lid and open it, and the remote machines used to sit there. A
connection held across sleep points at a path that stopped existing while the
lid was shut, and neither end has anything to say about it — ssh works it out
eventually, from keepalives that had been set to take two minutes, and two
minutes of dead panes is indistinguishable from never reconnecting.

HerdX now reattaches every remote machine the moment the Mac wakes, which is
the one moment the staleness is known rather than waited for. Measured against
four machines: all four back inside a second. For the drops nothing announces
— a Wi-Fi roam, a VPN flap, a machine rebooting — the wait is now forty
seconds rather than two minutes.

## Fixes

- **Hibernation could close a workspace whose agent had just started
  working.** Everything it knew was read before the close went out, so an
  agent that picked up a turn in that window was ended mid-turn. It now looks
  once more immediately before closing, and gives up if anything has changed —
  including a tab opened since, which would have been thrown away unsaved.
- **Hibernation could save a workspace it can never bring back.** herdr will
  not rebuild a tab of more than 24 panes, or one split deeper than 16, but it
  will happily let you make one and export it. Such a workspace was saved,
  closed, and then failed every attempt to revive it. It is now left alone.
- **Reviving a workspace zoomed the wrong pane** in every tab but the first.
- **Setting up a new machine could type into the wrong pane.** The installer
  made a tab and then waited for the focus to move, which a click somewhere
  else also satisfies — and then typed a command and a newline into whatever
  was there. It now uses the pane herdr says it made.
- **Mouse clicks were reported at the wrong column.** A pane halfway across
  the window told the program inside it that every click was halfway across
  the window, which is every click in the wrong place for anything that reads
  the mouse. Dragging out of a pane, or releasing outside every pane, could
  also send the press and the release to two different programs.
- **Copy mode and a mouse selection disagreed about what would be copied** —
  the highlight followed the mouse while `y` copied where copy mode had been.
  And a copy-mode key pressed while the server was still answering the last
  one moved from the old position, so `wl` landed a column short.
- **A reconnect came back in the wrong colours.** A server starts every
  connection on its own default theme and HerdX had stopped telling it
  otherwise. The same was true of focus: a reconnected window could sit there
  looking unfocused to everything running in it.
- **⌃b typed into a text field could close a pane.** Settings, the Machines
  sheet and every rename prompt now keep their own keystrokes, as does an
  input method mid-composition.
- **HerdX could quit outright** when the herdr server went away at the wrong
  moment during a hibernate or revive.
- **A machine that failed to connect sometimes explained itself with nothing
  at all**, because the thread reading its error output had stopped on a
  character split across two reads.
- **Connections could accumulate invisibly.** A request whose reply never
  arrived kept its whole session alive — sockets, ssh processes and all — for
  as long as the app ran.
